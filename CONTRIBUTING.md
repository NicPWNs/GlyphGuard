# Contributing to GlyphGuard

Thanks for helping make text tell the truth. Bug reports, missed attacks, false positives,
docs and code are all welcome.

## Reporting a missed attack or a false positive

These are the most valuable reports. Please use the issue forms, and **never paste raw
hidden characters**: they vanish or get mangled in issue trackers and terminals. Instead,
paste the escaped form:

```console
glyphguard inspect --format json < sample.txt     # includes the code points of every finding
python -c "print(ascii(open('sample.txt', encoding='utf-8').read()))"
```

If a bypass lets an attack get past a deployed system, report it privately instead (see
[SECURITY.md](SECURITY.md)).

## House rules

- **Source and data files are pure ASCII.** Write every non-ASCII character as an escape:
  `\N{ZERO WIDTH SPACE}` or a backslash-u escape in Python, and the escaped form in TOML.
  A hidden character in this repository could hide in plain sight, and
  `tests/test_repo_hygiene.py` runs GlyphGuard over its own sources to enforce the rule.
- **Technique IDs are forever.** Never renumber or reuse an ID in `catalog.toml`; mark a
  retired technique `deprecated = true`.
- **No false positives on real text.** Any change to a detector must keep
  `tests/vectors/benign.toml` clean. Add a benign sample when you learn about a new
  legitimate use of a character.
- **No runtime dependencies.** The core stays pure Python and standard library. Optional
  integrations go behind extras.

## Adding a technique

1. Add an entry to `src/glyphguard/catalog.toml`: the next free ID in its family, a slug,
   a default severity, a summary, and CWE, ATLAS and reference links.
2. Detect it in `src/glyphguard/detect.py`. Every flagged code point must be reachable
   from the trigger pattern or the mark patterns. If you add a new class of character,
   extend `_TRIGGER_CATEGORIES` or the explicit ranges.
3. Add attack vectors to `tests/vectors/attacks.toml`. Include `payload` if something
   hidden should be decoded and `sanitized` for the expected `llm-input` result.
   `test_every_technique_has_a_vector` fails until you do.
4. Decide what each profile in `src/glyphguard/profiles.toml` does with it. Family
   defaults usually cover it.
5. Run `python scripts/bench.py` if the change touches the hot path.

## Unicode data

`src/glyphguard/_data/ucd.py` is generated. To move to a new Unicode version, change
`UNICODE_VERSION` in `scripts/gen_data.py` and run it; CI checks the committed tables with
`python scripts/gen_data.py --check`. The weekly **Unicode watch** workflow opens an issue
when a newer Unicode version is published.

## Releasing

The package version comes from the git tag (via `hatch-vcs`), so there is no version
number to bump in the code.

1. In `CHANGELOG.md`, rename `## [Unreleased]` to `## [0.1.0] - YYYY-MM-DD` (and start a
   new empty `## [Unreleased]` above it). Merge that to `main`.
2. Go to **Actions > Release > Run workflow** and enter `0.1.0`. You can also push a
   `v0.1.0` tag yourself.
3. The workflow creates the tag, builds the sdist and wheel, tests the built wheel, and
   publishes a GitHub Release with the CHANGELOG section as its notes. Versions such as
   `0.2.0rc1` are marked as pre-releases.

Other details:

- **PyPI:** publishing uses Trusted Publishing and is off by default. To turn it on, add
  a trusted publisher on PyPI (owner `NicPWNs`, repository `GlyphGuard`, workflow
  `release.yml`, environment `pypi`), then set the repository variable
  `PYPI_PUBLISH=true`.
- **Build provenance:** attestations are generated automatically once the repository is
  public.

## Brand assets

The logo, mark, social card and terminal demo in `docs/assets/` are generated by
`scripts/make_brand.py`. It needs `pip install fonttools resvg-py` and the JetBrains Mono
TTFs; see its docstring. Regenerate `demo.svg` after changing CLI output.
